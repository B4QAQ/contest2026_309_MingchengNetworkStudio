# Rockchip RK3506 NAND 分区表 (openvela, v6 — A/B 双分区 OTA + amp 分区 (M0 由 U-Boot 加载放行))
#
# 单位: 块 (1 block = 1 sector = 512 bytes)
# Flash layout: 从 0x800 (sector 4) 开始, 所有分区 128KB 对齐
# v6: 增加 amp 分区 (M0 固件交由 U-Boot 加载放行, 见 AGENTS.md rpmsg 行)
#
# 分区       起始        大小          用途
# vnvm      0x00000800  0x00001000  2MB    NV 存储 (MAC 地址等)
# uboot     0x00001800  0x00004000  8MB    U-Boot 引导加载器 (预编译 FIT)
# misc      0x00005800  0x00001000  2MB    BCB(0) + AvbABData(2048) A/B 槽位元数据
# boot_a    0x00006800  0x00005000  10MB   NuttX 内核 A 槽 (FIT 镜像)
# boot_b    0x0000B800  0x00005000  10MB   NuttX 内核 B 槽 (FIT 镜像)
# amp       0x00010800  0x00000800  1MB    M0 固件 FIT (amp.img, standalone, U-Boot 加载放行)
# userdata  0x00011000  -           剩余   用户数据 (grow, littlefs /data)
#
# A/B 机制 (U-Boot CONFIG_ANDROID_AB, boot_fit):
#   - U-Boot 读 misc 偏移 2048 的 AvbABData, 选 priority 最高且
#     (successful_boot || tries_remaining>0) 的槽, 写 android_slotsufix=_x,
#     再按名字 boot_a/boot_b 读 FIT 引导
#   - 元数据缺失/校验错: U-Boot 自动重置为默认 (A=15/7/0, B=14/7/0)
#   - boot_fit 本身不递减 tries; 递减/回滚由 NuttX rcS 的 `ota bootcheck`
#     (HD_RK3506_OTACMD) 完成, `ota confirm` 确认健康后转为永久槽
#   - recovery/oem/system 等不再需要 (无 Android 恢复流程), 删除以给
#     userdata 让位; 旧版镜像与此布局不兼容, 需 `upgrade_tool lf` 全量刷
#
